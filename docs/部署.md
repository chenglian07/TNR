## 2. 两个必须知道的坑

### 坑 1：venv 一定要 `--system-site-packages`

`picamera2` 是 apt 装的系统包，普通 venv 看不到它（`ImportError: picamera2`）。

```bash
python3 -m venv --system-site-packages ~/venvs/catvision   # ✓
python3 -m venv ~/venvs/catvision                          # ✗ 后面一定报错
```

### 坑 2：帧不能写 SD 卡

SD 卡写入寿命有限，3fps × 每帧 ~200KB = 每天 ~50GB 的写入量，几天就把卡写坏。
默认落在 `/dev/shm`（内存盘），重启即清，正好符合原型「不需要留存历史帧」的定位。

```bash
df -h /dev/shm        # 默认只给一半内存，Pi4 1GB 上是 450MB 左右
```

如果内存特别紧张，把 `fstab` 里的 `/dev/shm` 调小，或改用 `--keep-frames 30` 少留几帧。

## 3. 关桌面环境（强烈建议）

1GB 内存的机器上，桌面环境占 ~269MB，开机要 3 分钟。

```bash
sudo systemctl set-default multi-user.target
sudo reboot
```

开机降到 ~30 秒，可用内存多出 ~270MB。**这在跑两个 AI 模型时是生与死的差别。**

## 4. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `ImportError: picamera2` | venv 没带 `--system-site-packages` | 重建 venv |
| `ModuleNotFoundError: catvision_contracts` | 没装包 | `pip install -e ~/catvision` |
| CSI 打不开 | 排线松 / 没启用 | `rpicam-still -o /tmp/t.jpg --timeout 2000` |
| 采集很慢 | `vcgencmd get_throttled` 非 0 | 换 5V/3A 电源 |
| 前几帧全黑 | 曝光还没收敛 | `CsiSource(warmup=1.0)`（默认已开） |
| 内存不够 / OOM | 两个模型同时加载 | 关桌面、限帧 2fps、模型换小、开 NCNN |
| SSH 断连 | WiFi 掉 / 内存耗尽 | 优先上有线网 |

## 6. 猫/非猫分类器上线记录（2026-10-23 实测）

从 ESP32-S3-EYE 转到树莓派后，第一个真正跑起来的模型：MobileNetV2 二分类，
输入 224×224，类别顺序 `["cat", "notcat"]`，导出为 ONNX。

### 6.1 装什么

```bash
source ~/venvs/catvision/bin/activate
pip install onnxruntime            # 1.31.0，有 aarch64 + cp313 的轮子，直接装
```

**不要装 `opencv-python`**：分类器已经改成只用 numpy + Pillow 做预处理，
Pi 上现成的库就够，省下 ~60MB 内存和一大堆依赖。TP 只有 1GB，这一步很值。

### 6.2 模型放哪

```bash
scp models/cat_vs_notcat.onnx lyx@192.168.31.252:~/catvision/models/
```

- 文件 8.45MB，MD5 `7fd6ed39804627e89b564e0585446821`
- `models/*.onnx` 在 `.gitignore` 里，模型不进 Git，靠 scp 同步
- 输入 `[1,3,224,224]` float32，输出 `[1,2]` **logits**（不是概率，用前必须 softmax）

### 6.3 实测性能（4 核，欠压节流状态下）

| 项 | 数值 |
|---|---|
| 模型加载 | 148 ms |
| 内存增量 | +38 MB（进程 RSS 62.6 → 100.7 MB） |
| 单帧推理 @1 线程 | 287 ms（3.5 FPS） |
| 单帧推理 @2 线程 | 170 ms（5.9 FPS） |
| 单帧推理 @4 线程 | **119 ms（8.4 FPS）** |
| 取流 + 推理全链路 | 3.7 + 145 ≈ 149 ms/帧 → **≈6.7 FPS 可持续** |

结论：**4 线程**是甜点。摄像头取流本身只要 ~4ms，瓶颈全在推理；
`capture_array` 给的是 RGB888，可以直接喂，不用再转色。

### 6.4 怎么验

```bash
cd ~/catvision

# 1) 单图 + 延迟
python scripts/bench_classifier.py --model models/cat_vs_notcat.onnx \
    --images "tests/fixtures/classifier/*.png" --repeat 20 --threads 4

# 2) 摄像头实时演示（帧写 /dev/shm，别写 SD 卡）
python scripts/pi_live_demo.py --frames 30 --fps 5 --save-dir /dev/shm/shots

# 3) 单测
python -m pytest tests/test_cat_classifier.py -q
```

实测分类结果（Pi 与 PC 一致）：

| 图 | p_cat | 判定 |
|---|---|---|
| `chelsea_cat.png`（真猫） | 0.9999 | cat |
| `coffee_notcat.png` | 0.0000 | notcat |
| `astronaut_notcat.png` | 0.0000 | notcat |
| 现场摄像头帧 | 0.0107~0.0284 | notcat |

### 6.5 两个坑

1. **模型输出是 logits**。`cat_classifier.py` 里已经做了 softmax；
   如果哪次导出改成带 softmax 的图，就会双重 softmax，置信度全挤在 0.5 附近。
2. **`vcgencmd get_throttled = 0x50005` 还在**。上面的数字是欠压节流下测的，
   换了 5V/3A 电源只会更快。反过来说：现在这组数字是「最差情况」。

### 6.6 在测试集上评估准确率

`test_data/` 按标签分文件夹（15 张猫 + 15 张非猫），上传后直接跑：

```bash
scp -r test_data pi4-cat:catvision/
ssh pi4-cat "cd ~/catvision && ~/venvs/catvision/bin/python scripts/evaluate_accuracy.py --data-dir test_data"
```

2026-10-23 实测（Pi 4B，4 线程）：

| 指标 | 数值 |
|---|---|
| 准确率 | **100.00%**（30/30） |
| 精确率 / 召回率 / F1（cat） | 100% / 100% / 100% |
| 混淆矩阵 | TP 15, FN 0, FP 0, TN 15 |
| 置信度 | 猫 ≥ 0.9979，非猫 ≤ 0.1107 |
| 单张耗时 | 中位 168 ms（均值含首帧预热，偏高） |

> 置信度极度两极分化（最接近边界的猫图也有 0.998），说明模型在这批图上**过自信**。
> 这批图来自 `cats-vs-notcats/valid`，场景比较「干净」；真实摄像头画面（比如装反的那张）
> 判 notcat 时 p_cat=0.0007。要定阈值，得用真实场景的难负样本，别用这批干净数据。
